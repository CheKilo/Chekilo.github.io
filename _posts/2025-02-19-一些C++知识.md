#### 一、基础语法
##### **1、为什么 static 函数不能用 const 修饰？**

因为 const 修饰成员函数本质上是使用 const 修饰 this 指针，而 static 函数属于类，所以没有 this 指针。

##### **2、模板template、const和define定义常数用谁更好？**
如果需要定义普通的常量：优先使用 const，因为它具有类型安全、作用域明确等优点，能避免很多潜在的错误。

如果需要在编译期进行复杂的计算并得到常量：可以考虑使用模板元编程，但要注意其语法复杂度。

尽量避免使用 #define 定义常量：除非是在一些简单的、对类型要求不严格的场景下，或者需要定义一些简单的符号常量。


##### **3、char a[3], char a[], char*a 的区别？**
char a[3] 是固定大小的数组，char a[] 数组大小由初始化内容决定，而 char* a 是指针，它本身不代表固定大小的内存块，只是存储一个地址。


##### **4、宏定义和内联函数的区别？**
宏定义：宏定义只是简单的文本替换，不进行类型检查。这意味着在使用宏时，传递的参数可以是任意类型，编译器不会对参数类型进行验证，容易导致潜在的错误。

内联函数：内联函数是真正的函数，编译器会对函数的参数和返回值进行类型检查。如果传递的参数类型不匹配，编译器会报错，从而提高代码的安全性。

除此之外，inline函数还可以解决ODR问题。

当一个函数被声明为 inline 时，它在多个翻译单元（源文件）中可以有多个定义，只要这些定义是相同的，并且在每个使用该函数的翻译单元中都有定义，就不会违反 ODR。


##### **5、声明和定义的区别？**
声明不分配内存，而定义会为变量分配内存空间，为函数和类生成具体的实现代码。

声明可以多次出现，只要保证一致性即可；而定义在一个程序中通常只能出现一次（内联函数等特殊情况除外），否则会违反单一定义规则（ODR）


##### **6、static的作用？**
当 static 用于修饰全局变量时，它会将该变量的作用域限制在定义它的源文件内。普通全局变量的作用域是整个程序，在其他源文件中可以通过 extern 关键字进行声明并使用；而静态全局变量只能在定义它的文件中被访问，其他文件无法使用，这样可以避免不同文件中同名全局变量的命名冲突。

当 static 用于修饰局部变量时，该变量的生命周期会从函数调用期间延长到整个程序运行期间。普通局部变量在函数调用结束后就会被销毁，而静态局部变量只会在第一次调用函数时进行初始化，之后每次调用函数时，该变量会保留上一次调用结束时的值。

当 static 用于修饰函数时，它会将该函数的作用域限制在定义它的源文件内。普通函数的作用域是整个程序，在其他源文件中可以通过 extern 关键字进行声明并调用；而静态函数只能在定义它的文件中被调用，其他文件无法访问，这样可以避免不同文件中同名函数的命名冲突。

在 C++ 中，当 static 用于修饰类的成员变量时，该变量会被所有类的对象共享，而不是每个对象都有一份副本。静态类成员变量需要在类外进行初始化，并且在类的定义中只是声明。

在 C++ 中，当 static 用于修饰类的成员函数时，该函数不依赖于类的对象，可以直接通过类名调用。静态类成员函数没有 this 指针，只能访问静态类成员变量和其他静态类成员函数。


##### **7、指针和引用的区别？**
指针是一个变量，它存储的是另一个对象的内存地址。可以通过解引用操作符 * 来访问指针所指向的对象。指针可以被重新赋值，指向不同的对象，也可以被赋值为 nullptr，表示不指向任何对象。

引用是对象的别名，它必须在定义时进行初始化，并且一旦初始化后，就不能再引用其他对象。引用本身不是一个对象，它没有自己独立的内存地址，只是作为所引用对象的另一个名称。

指针本身是一个变量，会占用一定的内存空间，用于存储所指向对象的地址。指针的大小取决于操作系统的位数，通常在 32 位系统上为 4 字节，在 64 位系统上为 8 字节。

引用不占用额外的内存空间，它只是所引用对象的别名，与所引用对象共享同一块内存。


##### **8、四种强制转换有什么区别？**
1、static_cast 主要用于基本数据类型之间的转换、具有继承关系的类对象指针或引用之间的转换，以及显式的类型转换。它在编译时进行类型检查，不进行运行时的类型检查。

在具有继承关系的类之间，static_cast 可以进行向上转换（从派生类指针或引用转换为基类指针或引用）和向下转换（从基类指针或引用转换为派生类指针或引用）。不过，向下转换时需要程序员自己确保转换的安全性，因为 static_cast 不会进行运行时的类型检查。

2、dynamic_cast 主要用于在类的继承层次结构中进行安全的向下转换和交叉转换。它在运行时进行类型检查，通过检查对象的实际类型来确定转换是否合法。如果转换不合法，对于指针类型会返回 nullptr，对于引用类型会抛出 std::bad_cast 异常。

3、const_cast 主要用于去除或添加对象的 const 或 volatile 属性。它只能用于改变对象的常量性或易变性，不能改变对象的类型。

当需要修改一个原本被声明为 const 的对象时，可以使用 const_cast 去除其 const 属性。但需要注意的是，这种做法只有在对象本身不是 const 对象时才是安全的。

4、reinterpret_cast 是最危险的一种强制转换，它可以将任何指针类型转换为其他指针类型，也可以将指针转换为整数类型，或者将整数类型转换为指针类型。它只是简单地重新解释指针的值，不进行任何类型检查。

##### **9、C语言中的struct和C++的有什么区别？**
1、访问权限：
* 在 C 语言里，struct 成员的访问权限没有明确的访问控制概念。所有成员默认都是公开的，可在结构体定义的作用域内自由访问，无论在结构体内部还是外部。
* C++ 中的 struct 成员默认访问权限是 public，不过它支持面向对象编程的访问控制机制，允许使用 private、protected 和 public 关键字来限定成员的访问权限。

2、成员函数：
* C 语言的 struct 只能包含数据成员，不能包含函数。若要操作结构体的数据，需定义独立的函数，并将结构体作为参数传递。
* C++ 的 struct 可以包含成员函数，这些成员函数可以直接访问结构体的成员变量，使代码的封装性和可读性更好。

3、继承和多态
* C 语言不支持继承和多态的概念，struct 只是简单的数据聚合，无法实现代码的复用和多态性。
* C++ 中的 struct 支持继承和多态。struct 可以从其他 struct 或 class 继承，也可以使用虚函数实现多态。

4、类型定义和使用
* 在 C 语言中，使用 struct 定义类型后，声明变量时需要带上 struct 关键字。
* 在 C++ 中，声明 struct 类型的变量时可以省略 struct 关键字。

5、构造函数和析构函数
* C 语言的 struct 没有构造函数和析构函数的概念，无法在创建和销毁结构体对象时自动执行特定的代码。
* C++ 的 struct 可以有构造函数和析构函数，用于对象的初始化和清理工作。

##### **10、malloc与new的区别？**
1、内存分配:
* malloc：只负责分配指定大小的内存块，不会对分配的内存进行初始化。它返回一个 void* 类型的指针，需要手动将其转换为所需的指针类型。
* new：不仅会分配内存，还会调用对象的构造函数进行初始化。对于内置类型（如 int、double 等），如果不指定初始值，默认情况下不会进行初始化；但可以显式指定初始值。

2、内存释放
* malloc：使用 free 函数来释放由 malloc 分配的内存。free 函数只会释放内存，不会调用对象的析构函数。
* new：使用 delete 运算符来释放由 new 分配的内存。对于单个对象，使用 delete；对于数组，使用 delete[]。delete 会先调用对象的析构函数，然后再释放内存。

在这里注意，对于数组而言不一定非要调用delete[]，如果数组中存储的是POD类型对象，那么delete也可以释放对应的内存。

3、异常处理
* malloc：如果内存分配失败，malloc 会返回 NULL 指针，因此在使用 malloc 分配内存后，需要手动检查返回值是否为 NULL，以确保内存分配成功。
* new：如果内存分配失败，new 通常会抛出 std::bad_alloc 异常。可以使用 try-catch 块来捕获这个异常。

4、构造函数
* malloc：malloc 只是简单地分配内存，不会调用自定义类型的构造函数和析构函数。如果要使用自定义类型，需要手动调用构造函数和析构函数（在 C++ 中可以使用 placement new 来手动调用构造函数）。
* new：new 会自动调用自定义类型的构造函数进行对象的初始化，delete 会自动调用析构函数进行对象的清理，使用起来更加方便和安全。

5、底层原理
malloc 是 C 标准库中的一个函数，其底层实现依赖于操作系统提供的内存管理机制。在不同的操作系统中，malloc 的具体实现可能会有所不同，但大致的工作流程如下：

malloc 函数会根据请求的内存大小，向操作系统内核发起系统调用（如在 Linux 系统中是 brk 或 mmap）来获取内存。

* brk：当请求的内存较小（通常小于 128KB）时，malloc 会使用 brk 系统调用。brk 是通过移动数据段的结束地址（break 指针）来分配内存的，它会在进程的堆空间中分配连续的内存块。
* mmap：当请求的内存较大（通常大于等于 128KB）时，malloc 会使用 mmap 系统调用。mmap 会在进程的虚拟地址空间中映射一块新的内存区域，这块内存区域通常位于堆和栈之间的内存映射区域。
* malloc 函数会维护一个内存池，用于管理已经分配和未分配的内存块。当用户请求内存时，malloc 会先在内存池中查找是否有合适的空闲内存块，如果有则直接返回该内存块的地址；如果没有，则向操作系统申请新的内存。

new 是 C++ 中的一个运算符，它的底层实现依赖于 malloc 和构造函数的调用。new 的工作流程如下：

* new 运算符会调用 operator new 函数来分配内存。operator new 函数是一个全局函数，它的默认实现通常会调用 malloc 函数来完成实际的内存分配工作。
* 在成功分配内存后，new 运算符会调用对象的构造函数来初始化这块内存。构造函数会对对象的成员变量进行初始化，完成对象的创建过程。
* 如果内存分配和构造函数调用都成功，new 运算符会返回一个指向新创建对象的指针；如果内存分配失败，new 运算符通常会抛出 std::bad_alloc 异常。


##### **11、函数重载在二进制文件中怎么区分？**
编译器为了在二进制文件中区分重载函数，会对函数名进行修改，将函数的参数类型、返回值类型（某些编译器会考虑）等信息编码到新的函数名中，使得每个重载函数在二进制文件中都有一个唯一的标识符。


##### **12、.c和.cc相互调用为什么会报错？怎么解决？**
C++ 支持函数重载，为了在二进制层面区分同名但参数不同的函数，C++ 编译器会对函数名进行名字修饰（Name Mangling）。而 C 语言不支持函数重载，C 编译器不会对函数名进行修饰。因此，当 C 代码调用 C++ 函数或者 C++ 代码调用 C 函数时，由于名字修饰的差异，链接器可能无法找到正确的函数定义。

C 和 C++ 的类型系统存在一些细微的差异，例如 C++ 支持引用类型、类类型等，而 C 语言没有这些概念。如果在相互调用时传递了不兼容的类型，会导致编译或运行时错误。

解决方法：
* 使用 extern "C"，用于告诉 C++ 编译器按照 C 语言的规则来处理函数名，即不进行名字修饰。这样可以确保 C 代码和 C++ 代码在链接时能够正确找到函数定义。

##### **13、浅拷贝与深拷贝的区别？**
浅拷贝：
* 浅拷贝是指在复制对象时，只复制对象的基本数据成员的值，而对于对象中包含的指针成员，只是复制指针的值（即内存地址），而不复制指针所指向的内存内容。这意味着原对象和拷贝对象的指针成员会指向同一块内存区域。

深拷贝：
* 深拷贝是指在复制对象时，不仅复制对象的基本数据成员的值，还会为对象中包含的指针成员分配新的内存空间，并将原指针所指向的内存内容复制到新分配的内存中。这样，原对象和拷贝对象的指针成员会指向不同的内存区域，彼此独立。

#### 二、类
##### **1、类的三大特性是什么？**
封装 继承 多态。

##### **2、类的静态成员函数能访问非静态私有成员变量吗？**
如果将类对象作为参数传入静态成员函数的话，就可以访问。
如下：
```cpp
class base
{
public:
    base(): num(1)
    {
    }

    static void print(base& b)
    {
        cout << b.num << endl;
    }

private:
    int num;
};

int main()
{
    base b;
    base::print(b);
}
```
C++ 的访问控制规则（如private、protected和public）是基于类的。这意味着只要是在类的定义内部，无论是成员函数（包括静态成员函数）还是嵌套类，都可以访问该类的私有成员。


#### 三、智能指针
##### **1、make_shared() 相较于调用 shared_ptr 的构造函数，有什么性能优势？**

每个 std::shared_ptr 会指向一个控制块，如果使用 new 搭配构造函数的话，即需要为 new 分配一块内存，又需要为控制块分配一块内存。

而如果使用 make_shared() ，那么一次内存分配就足够了。那是因为 std::make_shared 会分配一块独立的内存既保存 new 对象又保存控制块。

##### **2、智能指针为什么避免传入裸指针？**
1、所有权转移问题
* 当将裸指针传递给智能指针时，如果裸指针已经被其他智能指针或手动管理，就可能导致多个智能指针管理同一块内存，从而在对象生命周期结束时出现双重释放的问题，这会引发未定义行为。

2、悬空指针风险
* 如果在将裸指针传递给智能指针后，又手动释放了该裸指针所指向的内存，智能指针在后续尝试释放内存时就会操作一个已经被释放的内存块，从而产生悬空指针。


##### **3、为什么单例中使用shared_ptr的构造函数，而不是make_shared函数？**
1、构造函数私有化
* 单例模式要求类的构造函数是私有的，以确保只能通过特定的静态方法来获取单例实例，防止外部直接创建对象。std::make_shared 是一个函数模板，它会尝试调用类的公共构造函数来创建对象。由于单例类的构造函数是私有的，std::make_shared 无法访问这些私有构造函数，从而无法正常创建单例对象。


##### **4、shared_ptr底层原理？**
引用计数是 std::shared_ptr 实现的核心机制。每个 std::shared_ptr 对象都会维护一个引用计数，该计数记录了有多少个 std::shared_ptr 对象共享同一个对象。当一个 std::shared_ptr 对象被创建并指向一个对象时，该对象的引用计数初始化为 1；当有新的 std::shared_ptr 对象也指向该对象时，引用计数加 1；当一个 std::shared_ptr 对象被销毁或不再指向该对象时，引用计数减 1。当引用计数变为 0 时，说明没有任何 std::shared_ptr 对象再引用该对象，此时 std::shared_ptr 会自动释放该对象所占用的内存。

底层实现结构，std::shared_ptr 通常包含两个主要部分：
* 指向对象的指针：用于指向实际的动态分配的对象。
* 指向控制块的指针：控制块是一个包含引用计数和其他相关信息的数据结构。控制块的主要作用是管理对象的生命周期，它记录了当前有多少个 std::shared_ptr 对象共享同一个对象。

**创建对象**

当使用 make_shared 创建一个新的对象时,make_shared 会完成两件事：
* 分配一块足够的内存，用于存储 Class 对象和控制块
* 调用 Class 的构造函数初始化对象，并将控制块中的引用计数初始化为 1。

**复制对象**
当一个 std::shared_ptr 对象被复制时：
* ptr2 会复制 ptr1 中指向对象的指针和指向控制块的指针。
* 控制块中的引用计数会加 1，此时引用计数变为 2，表示有两个 std::shared_ptr 对象共享同一个 MyClass 对象。

**移动对象**
当一个 std::shared_ptr 对象被移动时：
* ptr2 会接管 ptr1 中指向对象的指针和指向控制块的指针。
* ptr1 会被置为空，不再指向任何对象，控制块中的引用计数不变。

**对象销毁**
当一个 std::shared_ptr 对象的生命周期结束时：
* ptr 的析构函数会被调用。
* 析构函数会将控制块中的引用计数减 1。
* 如果引用计数变为 0，说明没有其他 std::shared_ptr 对象再引用该对象，析构函数会调用对象的析构函数销毁对象，并释放对象和控制块所占用的内存。


##### **5、shared_ptr怎么管理this指针？**
如果在类的成员函数中直接将 this 指针传递给 std::shared_ptr 构造函数来创建一个新的 std::shared_ptr 对象，会产生多个独立的引用计数，这可能导致对象被多次释放，引发未定义行为。

```cpp
#include <iostream>
#include <memory>

class BadExample {
public:
    std::shared_ptr<BadExample> getShared() {
        return std::shared_ptr<BadExample>(this); // 错误做法
    }
    ~BadExample() {
        std::cout << "BadExample destructor" << std::endl;
    }
};

int main() {
    std::shared_ptr<BadExample> ptr1 = std::make_shared<BadExample>();
    std::shared_ptr<BadExample> ptr2 = ptr1->getShared();
    // 程序结束时，ptr1 和 ptr2 会分别释放对象，导致双重释放
    return 0;
}
```
为了防止出现这种情况，使用 std::enable_shared_from_this 管理 this 指针。

std::enable_shared_from_this 是一个模板类，它为派生类提供了一个成员函数 shared_from_this()，用于安全地获取指向当前对象的 std::shared_ptr。

使用步骤如下：
* 让类继承自 std::enable_shared_from_this<类名>。
* 在类的成员函数中，通过调用 shared_from_this() 方法来获取指向当前对象的 std::shared_ptr。

```cpp
#include <iostream>
#include <memory>

class GoodExample : public std::enable_shared_from_this<GoodExample> {
public:
    std::shared_ptr<GoodExample> getShared() {
        return shared_from_this();
    }
    ~GoodExample() {
        std::cout << "GoodExample destructor" << std::endl;
    }
};

int main() {
    std::shared_ptr<GoodExample> ptr1 = std::make_shared<GoodExample>();
    std::shared_ptr<GoodExample> ptr2 = ptr1->getShared();
    std::cout << "ptr1 use count: " << ptr1.use_count() << std::endl;
    std::cout << "ptr2 use count: " << ptr2.use_count() << std::endl;
    // 程序结束时，对象只会被释放一次
    return 0;
}
```

**使用 std::enable_shared_from_this 的注意事项**
* 必须通过 std::shared_ptr 创建对象：std::enable_shared_from_this 依赖于对象已经被 std::shared_ptr 管理。如果对象不是通过 std::shared_ptr 创建的，调用 shared_from_this() 会导致未定义行为。 
* 避免在构造函数和析构函数中使用：在构造函数中，对象还没有被 std::shared_ptr 管理，调用 shared_from_this() 会导致未定义行为。在析构函数中，对象的引用计数可能已经变为 0，此时调用 shared_from_this() 也会导致未定义行为。

std::enable_shared_from_this 类的核心思想是维护一个指向当前对象的弱引用（std::weak_ptr）。

当通过 std::make_shared 或者 std::shared_ptr 的构造函数创建一个管理 std::enable_shared_from_this 派生类对象的 std::shared_ptr 时，会自动将这个弱引用指向该对象。

shared_from_this() 函数则是通过这个弱引用创建一个新的 std::shared_ptr (即调用弱引用的 lock 函数)，从而保证引用计数的正确管理。

std::enable_shared_from_this 中的 weak_this_ （在标准库实现里是类似功能的弱引用成员）指向派生类对象这一过程，是在使用 std::shared_ptr 来管理派生类对象时自动完成的。

在 shared_ptr 类中，会有一定的机制来检查当前管理对象是否继承自 enable_shared_from_this<T> 类，如果是，则将 weak_this_ 指向当前对象。

##### **6、智能指针是线程安全的吗？**
1、std::unique_ptr 不提供线程安全的操作保证，但从其语义本身来看在多线程场景下不容易出现线程安全问题。
* std::unique_ptr 是独占式智能指针，同一时间只能有一个 std::unique_ptr 指向某个对象。这意味着它不支持多个线程同时共享同一个 std::unique_ptr 的情况。如果多个线程需要访问同一个对象，通常不会使用 std::unique_ptr。
* 只要每个线程拥有自己独立的 std::unique_ptr 实例，就不会有线程安全问题，因为它的操作都是针对单个独占的资源进行的。

2、std::shared_ptr 的引用计数操作是线程安全的，但对其管理的对象的访问和修改通常不是线程安全的。
* std::shared_ptr 内部使用原子操作来管理引用计数，这意味着多个线程可以同时对引用计数进行增加或减少操作，而不会出现数据竞争的问题。例如，当多个线程同时拷贝一个 std::shared_ptr 时，引用计数会正确地增加；当多个线程同时销毁 std::shared_ptr 时，引用计数也会正确地减少。
* 虽然引用计数是线程安全的，但 std::shared_ptr 管理的对象本身并没有提供线程安全的保证。如果多个线程同时访问和修改该对象，可能会导致数据竞争和未定义行为。因此，在多线程环境下访问和修改 std::shared_ptr 管理的对象时，需要使用同步机制（如互斥锁 std::mutex）来保证线程安全。

3、std::weak_ptr 本身的操作（如构造、析构、赋值、检查是否过期等）通常是线程安全的，因为它主要依赖于 std::shared_ptr 的引用计数。
* std::weak_ptr 不拥有对象，它只是对 std::shared_ptr 管理的对象的一个弱引用。其操作主要涉及到对 std::shared_ptr 引用计数的观察，而 std::shared_ptr 的引用计数操作是线程安全的，所以 std::weak_ptr 的基本操作在多线程环境下也是安全的。
* 不过，当通过 std::weak_ptr 创建 std::shared_ptr 时，需要确保这个过程是线程安全的，通常可以使用 std::weak_ptr::lock() 方法，该方法会原子地检查 std::weak_ptr 所引用的对象是否还存在。
* 使用weak_ptr的expired()接口是不安全的，而lock()接口是安全的。

#### 四、常用容器和算法
##### **1、vector和list的区别？**
vector：
* 基于动态数组实现。它在内存中分配一块连续的存储空间来存储元素，就像普通的数组一样，元素依次排列在这块连续的内存区域中。
* 当元素数量超过当前分配的内存大小时，std::vector 会重新分配一块更大的内存空间，并将原有的元素复制到新的内存中，然后释放原有的内存。

list：
* 基于双向链表实现。链表由一系列节点组成，每个节点包含数据和两个指针，分别指向前一个节点和后一个节点。
* 这些节点在内存中是分散存储的，通过指针相互连接形成一个双向链表。

##### **2、map和unordered_map的区别？**
map的底层是红黑树，而unordered_map的底层是哈希表。

std::map：
* 元素按照键的顺序进行排序，默认使用 std::less 比较函数，即键值从小到大排序。因此，遍历 std::map 时会按照键的升序顺序访问元素。
* 插入操作的时间复杂度为 O(logn)

std::unordered_map:
* 元素没有特定的顺序，元素的存储位置由哈希函数决定。因此，遍历时元素的顺序是不确定的。
* 平均情况下插入操作的时间复杂度为 O(1)，因为哈希表可以直接通过哈希函数计算出元素的存储位置。但在最坏情况下（如哈希冲突严重），时间复杂度可能会退化为 O(n)。

##### **6、容器可以传入引用吗？**
容器不能直接传入引用，因为引用只是别名，并没有内存空间。

如果想要在容器中传入引用，可以使用 std::reference_wrapper<> ，如下:

```cpp
#include <iostream>
#include <vector>
#include <functional>

int main() {
    int a = 10, b = 20, c = 30;
    // 创建一个存储 std::reference_wrapper<int> 的向量
    std::vector<std::reference_wrapper<int>> vec;

    // 使用 std::ref 将变量的引用存入向量
    vec.push_back(std::ref(a));
    vec.push_back(std::ref(b));
    vec.push_back(std::ref(c));

    // 通过引用包装器修改原始变量的值
    for (auto& ref : vec) {
        ref.get() *= 2;
    }

    // 输出修改后变量的值
    std::cout << "a: " << a << ", b: " << b << ", c: " << c << std::endl;

    return 0;
}
```

std::ref 和 std::cref 都是用来创建 std::reference_wrapper 对象的，前者创建的是普通引用，后者则是常引用。

#### 八、C++内存管理
##### **1、C++内存模型是什么样的？**
从大体上可以分为全局区、代码段、堆区和栈区。

全局区可以再分为只读数据段、未初始化变量区、初始化变量区，全局区主要用于存储全局变量和静态变量。

全局区：
* 如果全局常量或者静态常量的值需要在运行时才能确定，那么它们会存储在全局区（也叫静态区）。
* 类的虚表也会存储在全局区的只读数据段中

代码段：
* 函数体：C++ 程序中所有函数的代码都存储在代码段，包括用户自定义的函数、类的成员函数以及标准库函数的机器码。
* 内联函数：虽然内联函数在调用处会被展开，但它们原本的代码定义仍然存储在代码段。不过编译器可能会根据具体情况进行优化，在某些情况下不会将内联函数的代码保留在代码段。
* 常量数据：字符串字面量（如 "Hello, World!"）存储在代码段，使用 const 修饰的全局变量，如果其值在编译时可以确定，也会存储在代码段。
