### 1.引言
ques1：如果要训练一个70B参数的大模型，有15T个token，在1024张H100上需要训练多长时间？
{:.info}

```python
total_flops = 6 * 70e9 * 15e12
assert h100_flops_per_sec = 1979e12/2
mfu = 0.5
flops_per_day = h100_flops_per_sec * mfu * 1024 * 60 * 60 * 24
days = total_flops / flops_per_day
```
MFU是AI芯片性能评估中的核心指标，全称“Model FLOPs Utilization”（模型浮点运算利用率）。其核心思想是：衡量模型实际使用的浮点运算量与芯片理论峰值浮点运算量的比值，反映硬件资源（如GPU、TPU的算力）是否被充分用于模型训练或推理。

MFU的数学表达式为：
$$
MFU = \frac{\text{实际模型FLOPs}}{\text{芯片理论峰值FLOPs} \times \text{运行时间}}
$$ 

代入计算后，得到最终days=143.927天，也就是说，如果要在1024张H100上，用15T个token训练一个70B参数的大模型，需要143.927天。

ques2:8张H100，使用adam优化器，你可以训练多大参数的模型？
{:.info}

```python
h100_bytes = 80e9
bytes_per_parameter = 4 + 4 + (4 + 4)  # parameters， gradients， optimizer states
num_parameters = (h100_bytes * 8) / bytes_per_parameter
```

代入计算后，答案会是40B参数。

### 2.Memory accounting
几乎所有深度学习中涉及到的tensor，都是以浮点数(float)的形式存储的，比如一个1000x1000的矩阵，它就是一个1000x1000的float数组。

而float32是最普遍的浮点数类型，它有1位表示符号，8位表示指数，23位表示尾数，所以float32的精度为2^-23，也就是10^-7，所以float32的精度是10^-7。

指数用来表示动态范围，而尾数用来表示精度，所以float32的动态范围是2^128，精度是10^-7。

![浮点数图](/img/in-post/2025-12-25/image.png)

这些tensors的内存占用也比较好算，比如一个4x4的矩阵，它的内存占用就是4x4x4=64字节(因为float32是4字节)

float32被称为单精度，或者全精度，基本上是深度学习中使用最高精度的浮点数类型了。

而与之相对的，float16被称为半精度，或者半浮点数，它只有1位表示符号，5位表示指数，10位表示尾数，所以精度为2^-10，也就是10^-3，动态范围是2^15，精度是10^-3。

但在实际场景中，其实我们更关心浮点数的动态范围，而不是精度，所以google在2018年提出了bfloat16(brain floating point)，它只有1位表示符号，8位表示指数，7位表示尾数，精度为2^-7，动态范围是2^8，精度是10^-2。

可以观察出来，bf16有着与fp16相同的内存占用，但却拥有和fp32相同的动态范围，所以它非常适合用于深度学习中。

虽然但是，对于计算来说使用bf16是很好的，但对于存储来说，bf16的精度太低了，所以一般对于存储优化器状态和参数时，仍旧还是会使用fp32。

当然，有32和16，自然就有fp8。

fp8有两种变体，一种指数位多，一种尾数位多，取决于你需要更高的精度还是更高的动态范围。

使用fp32来进行训练自然是最好的，但fp32的内存占用太大。可如果全部使用fp16、bf16甚至fp8，对于训练来说是冒着极大风险并且不稳定的，所以一般会使用混合精度训练。

### 3.Compute accounting
对于tensors而言，默认一般是存放在cpu上的，而gpu上的tensor，一般会使用cudaMalloc来申请内存，使用cudaFree来释放内存。

我们可以使用pytorch的to方法，将tensor从一个设备迁移到另一个设备，比如将tensor从cpu迁移到gpu，或者从gpu迁移到cpu(当然，这里cpu和gpu之间的数据传输是有开销的)。

也可以直接在gpu上创建tensor，比如torch.zeros(1024, 1024, device='cuda')。

#### 3.1 tensor在pytorch中的存储
在pytorch中，tensor的存储方式有两种，一种是CPU上的存储，一种是GPU上的存储。

不论哪一种，tensor都是一个指向内存某块区域的一个指针。

它会有一个stride，用来表示tensor中每个维度的内存偏移量，比如一个2x3的tensor，它的stride就是(3, 1)，表示第一个维度的内存偏移量是3，第二个维度的内存偏移量是1。

具体如何理解呢，stride(0) = 3, 就是说你需要跨越3个元素，才能访问到下一行，stride(1) = 1, 就是说你需要跨越1个元素，才能访问到下一列。

#### 3.2 slicing
张量的存储是可以复用的，大多数操作都不会触发新的内存分配，而是创建了一个视图。所以当你对某个张量进行修改时，另一个张量也会被修改。

在pytorch中，你可以用[]来访问张量的元素，比如tensor[0, 1]，表示访问tensor的第0行第1列的元素。也可以用y = x[0]或者，y = x[:,1]的方式，来获取x张量的某个视图。

除此之外，pytorch还提供了view方法，来创建一个视图，比如x.view(2, 3)，表示将x前两行后三列的元素制作出一个切片，作为一个视图返回。

以上操作都不会触发新的内存分配，而是创建了一个视图，所以当你对某个张量进行修改时，另一个张量也会被修改。

有时候部分操作会使得张量变得不连续，比如说x.view(2, 3)，就会使得x变得不连续，因为x的stride(0) = 3，stride(1) = 1，所以它无法通过stride来访问到第0行第1列的元素，所以它就变得不连续了。

或者是创建了某个张量的转置视图，比如x.transpose(1, 0)，也会使得x变得不连续，因为x的stride(0) = 1，stride(1) = 3，所以它无法通过stride来访问到第0行第1列的元素，所以它就变得不连续了。

这里需要多提一嘴，transpose在二维张量的层面上，可以看作是转置，但在多维张量的层面上，它更多是看做是交换维度，比如x.transpose(1, 0)，就会将x的维度0和维度1交换。

这种时候，我们可以使用contiguous方法，来使得张量变得连续，比如x.contiguous()。

当然，一旦使用了contiguous方法，就会触发新的内存分配，这时候就不再和原本的张量拥有相同的指针了。

同样的操作还有reshape，这也会触发新的内存分配，所以也会导致张量不再和原本的张量拥有相同的指针。

#### 3.3 element-wise
逐元素操作显然是会触发内存分配的，因为它需要有一个新的地方来存储结果，例如x.pow(2)、x.sqrt()、x.rsqrt()、x + x、x * 2、x / 0.5等等。

这里有一个可能后面写作业比较有用的方法，那就是triu和tril，这两个方法可以用来提取张量的上三角或者下三角，比如x.triu()，就可以提取x的上三角，而x.tril()，就可以提取x的下三角。

比如说
x = torch.ones(3, 3).triu()，它会创建一个3x3的张量，它的上三角元素都是1，而下三角元素都是0，这可以被我们用于注意力掩码中。

#### 3.4 matmul
深度学习的核心就是矩阵乘法，它的实现方式有很多种，比如pytorch中的matmul，比如numpy中的dot，比如tensorflow中的matmul，比如pytorch中的bmm。

下面是一个例子：
```python
x = torch.ones(16, 32)
w = torch.ones(32, 16)
y = x @ w # 这个@就是matmul，也就是等价于y = torch.matmul(x, w)
assert y.size() == torch.size([16, 16])
```

PyTorch 中处理高维张量乘法的核心函数是 torch.matmul（或 @运算符），它会自动将张量分为“批次维度”（前面的维度）和“矩阵维度”（最后两个维度），然后对每个批次分别进行矩阵乘法。

最终计算结果，就是每个批次矩阵乘法的结果，然后组成一个新的张量。

例如:
```python
x = torch.ones(4, 8, 16, 32)
w = torch.ones(32, 16)
y = x @ w
assert y.size() == torch.size([4, 8, 16, 16])
```

也就是说，可以看做4组8个16x32的矩阵，分别和32x16的矩阵相乘，然后组成一个新的16x16的矩阵，最后会得到4组8个16x16的矩阵。

#### 3.5 einops
einops是pytorch中一个比较实用的库，它可以帮助我们简化张量的操作，比如

```python
import einops
x = torch.randn(4, 3, 16, 16)
y = einops.rearrange(x, 'b c h w -> b (c h w)')
```

这里，x是一个4x3x16x16的张量，而y是一个4x768的张量(可以直观从字符串看出，它将c h w三个维度合并成了一个维度，合并后的维度大小就是c*h*w)

除此之外，einops用于transpose时也会比较方便，比如：

```python
import einops
x = torch.randn(4, 3, 16, 16)
y = einops.rearrange(x, 'b c h w -> b h w c')
```

这样很轻松且直观的就将c h w三个维度给调换了，比使用torch.transpose要方便很多。
