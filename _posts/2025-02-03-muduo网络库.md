今天开始利用C++11来解构muduo网络库对boost库的依赖。

这个项目的代码中，成员变量会以 _ 结尾来区分普通变量。

### 1、noncopyable
```cpp
/**
 * noncopyable被继承后，派生类对象可以正常构造和析构，但是派生类对象
 * 不可以进行拷贝和赋值操作。
 */
class noncopyable
{
public:
    noncopyable(const nocopyable &) = delete;
    noncopyable &operator=(const nocopyable &) = delete;

protected:
    noncopyable() = default;
    ~noncopyable() = default;
};
```
上面的代码是muduo库中的一种技巧，如果你想要禁止一个类的拷贝和赋值操作，可以让那个类直接继承nocopyable类。

由于派生类对象构造时需要先调用基类的构造函数，因此当nocopyable的派生类想要进行赋值或者拷贝时，就会调用nocopyable的赋值或拷贝构造函数。

而由于nocopyable禁止了赋值和拷贝构造函数，因此派生类自然也就无法赋值和拷贝。

### 2、Logger日志
首先，对于Logger类的设计应该是单例的，否则每打印一段日志就创建一个日志类对象，这样的开销是浪费的。

其次，一个基本的日志类应该有多个等级，以此来区分不同程度的日志类别。

下面是Logger类的具体实现代码：

Logger.h

```cpp
#pragma once

#include <cstdio>
#include <string>

#include "noncopyable.h"

// LOG_INFO("%s %d", arg1, arg2)
#define LOG_INFO(logmsgFormat, ...)                                            \
  do {                                                                         \
    logger &logger = Logger::instance();                                       \
    logger.setLogLevel(INFO);                                                  \
    char buf[1024] = {0};                                                      \
    snprintf(buf, 1024, logmsgFormat, ##__VA_ARGS__);                          \
    logger.log(buf);                                                           \
  } while (0)

#define LOG_ERROR(logmsgFormat, ...)                                           \
  do {                                                                         \
    logger &logger = Logger::instance();                                       \
    logger.setLogLevel(ERROR);                                                 \
    char buf[1024] = {0};                                                      \
    snprintf(buf, 1024, logmsgFormat, ##__VA_ARGS__);                          \
    logger.log(buf);                                                           \
  } while (0)

#define LOG_FATAL(logmsgFormat, ...)                                           \
  do {                                                                         \
    logger &logger = Logger::instance();                                       \
    logger.setLogLevel(FATAL);                                                 \
    char buf[1024] = {0};                                                      \
    snprintf(buf, 1024, logmsgFormat, ##__VA_ARGS__);                          \
    logger.log(buf);                                                           \
  } while (0)

#ifdef MUDEBUG
#define LOG_DEBUG(logmsgFormat, ...)                                           \
  do {                                                                         \
    logger &logger = Logger::instance();                                       \
    logger.setLogLevel(DEBUG);                                                 \
    char buf[1024] = {0};                                                      \
    snprintf(buf, 1024, logmsgFormat, ##__VA_ARGS__);                          \
    logger.log(buf);                                                           \
  } while (0)
#else
#define LOG_DEBUG(logmsgFormat, ...)
#endif

// 定义日志的级别 INFO ERROR FATA DEBUG
enum LogLevel {
  INFO,  // 普通信息
  ERROR, // 错误信息
  FATAL, // CORE信息
  DEBUG  // 调试信息
};

// 输出一个日志类
class Logger : noncopyable {
public:
  // 获取日志唯一的实例
  static Logger &instance();
  // 设置日志级别
  void setLogLevel(int level);
  // 写日志
  void log(std::string msg);

private:
  int logLevel_;
  Logger() = default;
};
```

Logger.cc
```cpp
#include "Logger.h"

#include <iostream>

// 获取日志唯一的实例
Logger &Logger::instance() {
  static Logger logger;
  return logger;
};

// 设置日志级别
void Logger::setLogLevel(int level) { logLevel_ = level; }

// 写日志
void Logger::log(std::string msg) {
  switch (logLevel_) {
  case INFO:
    std::cout << "[INFO]";
    break;

  case ERROR:
    std::cout << "[ERROR]";
    break;

  case FATAL:
    std::cout << "[FATAL]";
    break;

  case DEBUG:
    std::cout << "[DEBUG]";
    break;

  default:
    break;
  }

  // 打印时间和msg
  std::cout << "print time" << ":" << msg << std::endl;
}
```
具体代码没什么复杂的，唯一的关键点就是使用了一个宏。

值得注意的是，代码中的宏使用了一个 do...while(0) 结构，这是一种常用的宏定义技巧，能确保宏在各种上下文中都能正确工作。

即使宏被用于条件语句（如 if 语句）中，do...while(0) 也能保证宏内部的代码块作为一个整体执行，避免出现语法错误。

__VA_ARGS__ 是一个预处理器标识符，它用于在宏定义里表示可变参数列表。当你定义一个带有可变参数的宏时，__VA_ARGS__ 会被替换为宏调用时传入的实际可变参数。

### 3、Timestamp时间
对于一个网络库而言，时间戳是必不可少的，本小节便是简单地实现一个时间类。

Timestamp.h
```cpp
#pragma once

#include <iostream>
#include <string>

class Timestamp {
public:
    Timestamp();
    explicit Timestamp(int64_t microSecondsSinceEpoch);
    static Timestamp now();
    std::string toString() const;
private:
    int64_t microSecondsSinceEpoch_;
};
```
Timestamp.cc
```cpp
#include "Timestamp.h"

#include <cstddef>
#include <time.h>

Timestamp::Timestamp() : microSecondsSinceEpoch_(0) {};

Timestamp::Timestamp(int64_t microSecondsSinceEpoch)
    : microSecondsSinceEpoch_(microSecondsSinceEpoch) {};

Timestamp Timestamp::now() {
  time_t ti = time(NULL);
  return Timestamp(ti);
};

std::string Timestamp::toString() const {
  char buf[128] = {0};
  tm *tm_time = localtime(&microSecondsSinceEpoch_);
  snprintf(buf, 128, "%4d/%02d/%02d %02d:%02d:%02d", 
        tm_time->tm_year + 1900,
        tm_time->tm_mon + 1,
        tm_time->tm_mday,
        tm_time->tm_hour,
        tm_time->tm_min,
        tm_time->tm_sec);
    return buf;
};
```
可以看见，在Timestamp的有参构造函数前使用了explicit修饰，这是为了防止隐式类型转换造成不确定行为，一般在有参构造函数前都会添加该关键词。

我们的时间类Timestamp主要实现两个功能，一个是 now() 另一个则是 toString()。

在这里，我们借助了头文件 <time.h> 中的 time_t ，这是一个包装好的结构体，可以便捷地获取不同时区的时间信息(包括但不限于年月日时分秒)。

### 5、InetAddress地址
作为一个网络库，对 socket 地址的封装自然是少不了的， InetAddress 便承担这些工作。

#### 本地字节序和网络字节序
在介绍接下来InetAdress的实现之前，我想先来介绍一下有关字节序的概念。

**本地字节序（Host Byte Order）**

本地字节序，也称为主机字节序，指的是计算机内部在存储多字节数据（如整数类型）时所采用的字节排列顺序。不同的计算机硬件架构可能会使用不同的本地字节序，主要分为大端字节序（Big - Endian）和小端字节序（Little - Endian）两种。

所谓大小端字节序指的是低地址处存放的是高字节(大端)，还是低字节(小端)，目前常见的 x86 架构的计算机系统采用的就是小端字节序。

**网络字节序（Network Byte Order）**

网络字节序是为了在不同字节序的计算机之间进行网络通信时保证数据的正确传输而规定的一种标准字节序。网络字节序采用的是大端字节序。

当不同字节序的计算机进行网络通信时，如果不进行字节序的转换，就可能会出现数据传输错误。

例如，一个小端字节序的计算机发送数据到一个大端字节序的计算机，如果不进行转换，接收方会按照自己的字节序来解释数据，从而得到错误的结果。

为了实现字节序之间的转换，C语言提供了一系列函数：

htons()：将 16 位的本地字节序转换为网络字节序（Host to Network Short）。

htonl()：将 32 位的本地字节序转换为网络字节序（Host to Network Long）。

ntohs()：将 16 位的网络字节序转换为本地字节序（Network to Host Short）。

ntohl()：将 32 位的网络字节序转换为本地字节序（Network to Host Long）。

#### InetAddress的实现

InetAddress.h
```cpp
#pragma once

#include "copyable.h"

#include <arpa/inet.h>
#include <cstdint>
#include <netinet/in.h>
#include <string>

// 封装socket地址类型
class InetAddress : public copyable {
public:
  explicit InetAddress(uint64_t port, std::string ip = "127.0.0.1");
  explicit InetAddress(const sockaddr_in &addr) : addr_(addr) {}

  std::string toIp() const;
  std::string toIpPort() const;
  uint16_t toPort() const;

  const sockaddr_in *getSockAddr() const { return &addr_;};

private:
  sockaddr_in addr_;
};
```
我们依旧保持良好习惯，在有参构造函数前使用 explicit 来修饰，不过细心的读者可能发现，在继承链上 InetAddress 公有继承了 copyable。

其实这里使用默认的私有继承也不影响功能，之所以特意使用 public 继承，主要是为了接口的规范。

在面向对象设计中，公有继承通常表示 “是一个（is - a）” 的关系，即 InetAddress 是一个可拷贝的对象，这符合其作为网络地址对象，需要在不同地方传递和复制的语义。

而私有继承表示 “实现了（has - a）” 的关系，表示因为特定的资源管理需求才拥有的概念，因此更适用于 noncopyable 这种设计理念。

这里的 sockaddr_in 是在 C 和 C++ 网络编程中用于表示 IPv4 地址信息的结构体，其主要作用是存储 IPv4 地址和端口号等相关信息。

InetAddress.cc
```cpp
#include "InetAddress.h"

#include <arpa/inet.h>
#include <cstdio>
#include <netinet/in.h>
#include <string.h>
#include <strings.h>
#include <sys/socket.h>

InetAddress::InetAddress(uint64_t port, std::string ip) {
  bzero(&addr_, sizeof addr_);

  // 设置地址族，AF_INET代表IPV4
  addr_.sin_family = AF_INET;

  // 将本地字节序转化为网络字节序
  addr_.sin_port = htons(port);

  // typedef uint32_t in_addr_t
  // in_addr_t s_addr
  // 所以s_addr就是一个32位无符号整数
  addr_.sin_addr.s_addr = inet_addr(ip.c_str());
};

std::string InetAddress::toIp() const {
  char buf[64] = {0};
  // 将网络字节序转化为本地字节序
  ::inet_ntop(AF_INET, &addr_.sin_addr, buf, sizeof buf);
  return buf;
};

std::string InetAddress::toIpPort() const {
  // ip:port
  char buf[64] = {0};
  // 将网络字节序转化为本地字节序
  ::inet_ntop(AF_INET, &addr_.sin_addr, buf, sizeof buf);
  size_t end = strlen(buf);
  // 将端口网络字节序转化为本地字节序
  uint16_t port = ntohs(addr_.sin_port);
  sprintf(buf + end, ":%u", port);
  return buf;
};

uint16_t InetAddress::toPort() const {
  // port
  // 将端口网络字节序转化为本地字节序
  return ntohs(addr_.sin_port);
};
```
大致的实现就是将socket地址的 ip 和 port ，在网络字节序和本地字节序间来回转换。

### 6、Channel通道

**Poller 的职责：**

Poller 的主要职责是进行 I/O 事件的监听和等待，它负责将多个文件描述符注册到 I/O 多路复用机制中，并在有事件发生时返回发生事件的文件描述符列表。通过将这一复杂的监听逻辑封装在 Poller 中，使得 Poller 的功能更加单一和明确。

**Channel 的职责：**

Channel 主要负责管理单个文件描述符及其相关的事件和回调函数。它只需要关注自身关联的文件描述符上的事件处理，而不需要关心如何进行事件的监听。这样，Channel 的代码更加简洁，专注于具体的事件处理逻辑，提高了代码的可读性和可维护性。

**EventLoop 的职责：**

EventLoop 作为整个事件循环的核心，负责协调 Poller 和 Channel 的工作。它调用 Poller 的 poll 方法等待事件发生，然后将发生事件的 Channel 列表传递给相应的 Channel 进行处理。通过这种职责分离，EventLoop 的代码也更加清晰，易于理解和维护。

一个线程有一个EventLoop，一个EventLoop里有一个Poller，一个Poller可以监听很多Channel。

下面直接来看看代码：

Channel.h
```cpp
#pragma once

#include "Timestamp.h"
#include "noncopyable.h"

#include <functional>
#include <memory>

// 在头文件只声明类型，在源文件包含头文件
class EventLoop;
class Timestamp;

/**
 * Channel理解为通道，封装了SocketFd和其感兴趣的event，如EPOLLIN、EPOLLOUT事件
 *还绑定了poller返回的具体事件
 */
class Channel : noncopyable {
public:
  // 事件回调
  using EventCallback = std::function<void()>;
  using ReadEventCallback = std::function<void(Timestamp)>;

  Channel(EventLoop *loop, int fd);
  ~Channel();

  // Poller监听到fd上发生对应事件后，调用该函数来处理事件(调用相应的回调函数)
  void handleEvent(Timestamp receiveTime);

  // 设置回调函数对象
  void setReadCallback(ReadEventCallback cb) { readCallback_ = std::move(cb); }
  void setWriteCallback(EventCallback cb) { writeCallback_ = std::move(cb); }
  void setCloseCallback(EventCallback cb) { closeCallback_ = std::move(cb); }
  void setErrorCallback(EventCallback cb) { errorCallback_ = std::move(cb); }

  // 防止channel被手动remove后，仍在执行回调操作
  void tie(const std::shared_ptr<void> &);

  // 设置fd事件状态
  void enableReading() {
    events_ |= kReadEvent;
    update();
  }
  void disableReading() {
    events_ &= ~kReadEvent;
    update();
  }
  void enableWriting() {
    events_ |= kWriteEvent;
    update();
  }
  void disableWriting() {
    events_ &= ~kWriteEvent;
    update();
  }
  void disableAll() {
    events_ = kNoneEvent;
    update();
  }

  // 获取和设置成员变量
  int fd() const { return fd_; }
  int event() const { return events_; }
  int index() const { return index_; }

  void set_revents(int revt) { revents_ = revt; }
  void set_index(int idx) { index_ = idx; }

  // 返回fd对应事件状态
  bool isWriting() const { return events_ & kWriteEvent; }
  bool isReading() const { return events_ & kReadEvent; }
  bool isNoneEvent() { return events_ == kNoneEvent; }

  // one loop per thread
  EventLoop *ownerLoop() { return loop_; }
  void remove();

private:
  // 将events注册到Poller
  void update();

  void handleEventWithGuard(Timestamp receiveTime);

  // 对感兴趣事件的描述
  static const int kNoneEvent;
  static const int kReadEvent;
  static const int kWriteEvent;

  EventLoop *loop_; // 事件循环
  const int fd_;    // Poller监听的对象
  int events_;      // 注册fd中感兴趣事件的类型(none read write)
  int revents_;     // Poller返回的具体发生的事件
  int index_;

  std::weak_ptr<void> tie_;
  bool tied_;

  // 因为Channel通道里，能够获知fd最终发生的具体事件revents，所以它负责调用具体事件的回调
  ReadEventCallback readCallback_;
  EventCallback writeCallback_;
  EventCallback closeCallback_;
  EventCallback errorCallback_;
};
```

大部分都是一些set、get函数，然后就是封装了一些回调函数的重命名。

由于注释写的还是比较清晰，因此不再赘述。
